# OPO 控制协议记录

本文只记录已由 OPPO Enco Air5 Pro 和 realme Buds T500 Pro 实机流量确认的行为。

## 传输

- 蓝牙服务：`0000079a-d102-11e1-9b23-00025b00a5a5`
- 传输方式：Classic Bluetooth RFCOMM
- 帧格式：`aa len b2 b3 opcode:u16be seq payloadLen:u16le payload...`
- `len` 是 base-128 变长整数，统计长度字段之后到帧尾的字节数；总帧长为 `1 + 长度字段字节数 + len`。不足 128 时占一字节，较长帧占两字节。
- 2026-09-07 实机：手机新增第三条 EQ 后，`22/81` 回包头为 `aa 8d 01 00 00 22 81 0e 86 00`，其中 `8d 01` = 141，负载 134 字节，总帧长 144。固定一字节长度会错位并吞掉后续响应。`ProtocolTests.testPhoneCreatedEQListWithVariableLengthHeaderAcrossEverySplit` 保存真实回包并覆盖每个拆包位置；官方插件 `Z6/b.java:b` 与 `T6/a.java:c` 独立确认该编码。
- 已观测帧没有尾部校验和。
- RFCOMM 可能拆分或合并帧，解码器会缓存残片并按 `aa` 重新同步。

## 已观测消息

- `00 01`：控制通道建立后的 hello。
- `04 02`：耳机主动上报状态。
- `04 04`：设置降噪模式，载荷为 `01 01 value`。
- `06 01` / `06 81`：Air5 Pro 电量查询与响应。
- `05 01` / `05 81`：Air5 Pro 设备版本查询与响应。
- `0f 01` / `0f 81`：Air5 Pro 均衡器预设查询与响应。
- `06 04` / `06 84`：Air5 Pro 均衡器预设写入与确认。
- `04 05`：Air5 Pro 均衡器预设主动上报。
- `0d 01` / `0d 81`：Air5 Pro 游戏模式查询与响应，功能编号为 `06`。
- `03 04` / `03 84`：Air5 Pro 游戏模式写入与确认。

状态载荷是 `type count` 加若干组 `id value`：

- `type 01`：电量；`id 01/02/03` 分别表示左耳、右耳、充电盒。Air5 Pro 的最高位表示正在充电，低七位表示百分比。
- `type 02`：放置状态；T500 Pro 使用 `00/03` 表示盒内/使用中，Air5 Pro 使用 `04/05` 表示盒内/盒外。现有证据不能区分放桌上与入耳；未知过渡值清除该耳旧位置，充电状态独立。
- `type 03`：降噪状态；不同型号使用各自的 Profile 解释值和宽度。

Air5 Pro 设备版本响应以 `00 entryCount` 开头，后面是 UTF-8 CSV 三元组。实机响应中的版本类型 `2` 是软件版本，按左耳、右耳、充电盒组合为固件版本，例如 `158.158.105`。

Air5 Pro 均衡器预设值为 `00` 至臻原音、`01` 澎湃低音、`02` 纯享人声。游戏模式使用功能编号 `06`，状态值 `00/01` 分别表示关闭和开启。两项设置都以耳机主动上报或查询回读作为界面状态，不使用本地乐观值。

## 写入规则

- OPPO Enco Air5 Pro 与 realme Buds T500 Pro 使用不同的模式值，写入必须经过对应型号 Profile。
- 未识别型号不允许写入。
- Set 命令与查询共用发送调度，且只发送一次；排队成功不代表发送或生效。实际发送后三秒内以匹配的状态报告或关联查询读回确认，窗口内不同值更新真实状态但不提前判定拒绝。超时解除 pending 并保留独立操作结果，界面不会乐观更新。
- 只允许已取得实机请求和响应的只读查询；查询按队列串行执行，并匹配 opcode 与 sequence。

任何新增命令都应先取得实机请求与回报，再加入 fixture 和测试；不能仅凭相似型号推断。

格式正确但尚未识别的 EQ 模式会保留原始模式值、清除旧预设高亮；自定义曲线仅按耳机返回列表中的 ID 识别。自定义 EQ 的协议结构和动作已核对官方手机插件，新增管理流程仍需实机验收。Alive Audio、双设备控制及独立入耳检测仍待补充协议证据。

### 自定义 EQ 列表与管理

- `22/01` 查询；`22/81` 返回状态字节、曲线数量、变长记录列表。空列表合法。
- 每条记录：选中标志、Int8 最小增益、Int8 最大增益、ID、UTF-8 名称字节数、名称、频段数，以及每段 UInt16LE 频率和 Int8 增益。
- `18/04` 写入：动作、最小增益、最大增益、ID、名称长度/名称、频段数/曲线；不包含选中标志。动作 1 新增（ID 0），2 修改并启用（含重命名、未修改曲线直接启用），3 删除。
- `06/05` 主动报告的负载直接从数量开始。支持更新列表；本地操作仍使用对应查询的完整读回确认。
- 新增确认使用耳机分配的新 ID；修改确认 ID、名称、频段、增益和选中状态；删除确认 ID 不再出现。发送成功或 SET 应答均不等于读回确认。
- 固件 158.158.105 已知 10 段：31/62/125/250/500/1000/2000/4000/8000/16000 Hz，范围 −6～+6 dB。曲线数量上限由耳机决定，不根据当前列表长度推断。
