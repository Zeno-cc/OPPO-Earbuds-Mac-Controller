## 推荐第一批

**第一批先做 001、002、003，以及 006 的快捷键错误清理。** 直接收益是反馈不丢、不说旧状态、减少动态效果真正生效；不需改变蓝牙协议或窗口架构。001 涉及反馈所有权，不能只改 1.6 秒这个数字；002 必须先定义事件何时失效。

**第二批做 004、005，补齐 006 的更新图标反馈。** 004 是最明显的视觉收益候选，但先收窄事务和稳定 pending 槽位，再调曲线；005 先暴露查询完成结果，才有真实的完成动效。

**最后做 007、008。** 现有弹性与停留曾获认可；先录制替换、悬停、中途反转与首次弹窗，再按文档的证据门槛推进。不为统一参数重写全部窗口。

## 实施和验证边界

- 保持 macOS 26、SwiftPM 与当前 Swift 5 language mode。技能中的更新语言建议不是本轮迁移理由。
- 保留设备回报确认、单次 SET、命令队列节流、generation 隔离；不增加轮询频率，不增加动画依赖。
- 原生 Button/Toggle/NSSlider/NSMenu 的输入与辅助功能语义保留；禁止给滑块跟手加补间。
- 文档审计完成不等于动效验收完成。`audit.md` 保留规划阶段的有限 AX 检查证据；本次实施的自动验证记录如下，不替代实机观感验收。
- 实施时只运行任务列明的针对性检查。完成一批后跑一次完整 `swift test` 和一次 `bash build.sh debug`，用途分别是防止跨控件回归和验证真实打包宿主；不为每个颜色/时长调整重复跑全量。
- 启动本地构建验收时避免与正式 App 同时控制耳机；测试包留在仓库，不覆盖 `/Applications`。提交与发布是后续独立动作。
